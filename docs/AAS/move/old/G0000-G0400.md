# G0000 – Foundation（SCAI：構造協働AIフレームワーク｜正式呼称：スカイ）

> **SCAI（Structured Cooperative AI Framework）公式宣言**
>
> SCAI（Structured Cooperative AI Framework）は、人間とAIが上下関係なく対等に協働し、構造化された文書を基盤として安全・整合的に作業を進めるための新しい標準体系である。
>
> * Structure-first（構造優先）
> * Cooperative（協働）
> * AI/Human Interpretability（双方可読性）
> * Consistency & Minimality（一貫性と最小性）
> * Automation-first（自動化前提）
>
> SCAIは文書倉庫ではなく、文書・仕様・規範・チェックリスト・AI指示・プロジェクト運用を統合することで、**“人間とAIが共に創造する作業環境”** を確立する。（背景・思想・存在理由）

## 1. 背景（Background）

ソフトウェア開発・文書管理・仕様設計の領域では、長年にわたり次のような構造的課題が存在してきた：

* 文書体系と開発体系が分裂し、整合が保てない
* 人間向けの記述と機械向け構造が乖離し、AI が適切に活用できない
* 文書・仕様・チェックリスト・設計書が個別最適で作られ、相互の整合性が崩れやすい
* フォーマットやテンプレートが乱立し、意図や責務の規律が希薄になる
* 情報の肥大化、属人性、更新停止による腐敗が発生する

これらは「個人開発」「小規模チーム」「大規模プロジェクト」のいずれでも発生しうる普遍的問題であり、AI 活用が進む現代においては、従来以上に整合性・構造性・透明性が求められている。

---

## 2. SCAI の存在理由（Purpose）

SCAI は、文書・仕様・構造化データ・開発プロセスといった disparate な成果物を、**単一の理念と構造で統合する**ために設計されている。目的は以下である：

* 文書体系と開発体系の統合による“唯一の構造軸（Single Structural Backbone）”の確立
* 構造化表現を基軸とした、人間と AI が共通で扱える情報体系の構築
* 冗長性・属人性・形式乱立を防ぎ、長期運用可能な知識体系を形成する
* 文書／仕様／チェックリスト／計画／コードレビューなどを断絶なく接続し、開発の整合性を維持する

SCAI は、形式やテンプレートそのものを増やすのではなく、「思想・原則・抽象構造」を中心に据えることで、変化に強い標準基盤を提供する。

---

## 3. 核となる思想（Core Philosophy）

SCAI の思想は、次の 5 つの価値観を基礎とする：

### 3.1 構造化の優越

文章ではなく、**構造**が情報の主となる。文章は構造を説明するレイヤであり、構造そのものではない。

### 3.2 AI と人間の共存設計

機械可読性と人間可読性を分離しつつ両立させることで、AI と人間が共通の基盤で思考・判断できるようにする。

### 3.3 最小であること（Minimality）

構造・文書・ルールは過剰に増やさず、必要最小限に保つ。複雑性は腐敗を招く。

### 3.4 原則主導設計（Principle-Driven）

発生するすべてのルールや文書は、上位原則（G0100）に従って設計されるべきであり、その逆ではない。

### 3.5 層構造による秩序（Layered Order）

理念 → 原則 → 抽象規範 → 分野フレームワーク → 手法 → プロジェクトという階層構造を維持し、混乱と責務の曖昧化を防ぐ。

---

## 4. SCAI が解決する問題（Problem Statement）

SCAI は次の問題領域に対し構造的解決を提供する：

### 4.1 情報の不整合

仕様・設計・テスト・チェックリストなどが個別に生成され、相互整合が失われる問題。

### 4.2 フォーマット乱立

テンプレート・書式・構造が無秩序に増え、理解や保守のコストが増大する問題。

### 4.3 プロセス断絶

要件・仕様・設計・実装・検証といった工程間で、**成果物同士の構造的一貫性が保てず、連続性が失われる問題。**

具体的な工程名には依存せず、どの開発モデルでも発生しうる“構造断絶”として扱う。

### 4.4 AI 解釈の困難

文章中心・非構造化の成果物は AI にとって曖昧であり、自動化や解析の妨げとなる問題。

---

## 5. Foundation と G0100 / G0200 の関係

* G0000（本書）は「思想・存在理由」を定義する層であり、原則や構造を定義しない。
* G0100 は思想を永続原則に抽象化した文書であり、行動指針・規範を扱う。
* G0200 はその原則を構造規範として落とし込み、A/B/C 層を接続するための抽象モデルである。

G0000 は SCAI 全体の“哲学的起点”であり、後続の原則・構造を正当化する役割を持つ。

# G0100 – Core Principles（SCAI フレームワーク｜正式呼称：スカイ）

> **SCAI とは？（A0100補足）**
>
> SCAI（Structured Cooperative AI Framework／スカイ）は、人間とAIが対等に協働し、構造化された文書を共通の基盤として作業するための体系である。本章で定義される普遍原則は、SCAI 全体の行動規範・設計規範として機能し、B層（分野構造）および C層（手法）に一方向的に適用される。（普遍原則・最終整形版）

> **先に読むべき文書：G0005 – SCAI Introduction（入門ガイド）**
> SCAI を初めて読む場合は、必ず G0005 を先に参照することを推奨する。G0005 は全体像・読み方・基本思想を短く案内し、本書（G0300）が扱う構造地図を理解しやすくするための前提となる。

## 1. 目的（Purpose）

G0100 は SCAI のすべての成果物（文書・構造・手法・AI指示・コード補助）に共通して適用される、**永続的で揺らがない原則**を体系的に定義する。

これらの原則は、G0200（抽象規範）や B/C 層（分野・手法）を含む全層の基盤であり、文書や手法の都合で変更されてはならない。
**原則 → 抽象規範 → 分野構造 → 手法** の一方向的な流れを支える最上位のルールである。

---

## 2. 適用範囲（Scope）

以下すべてに適用する：

* A層〜D層の全成果物
* 文書・構造化データ（YAML/JSON/DSL）・チェックリスト・SCD・コード規約
* AI による解析・生成・検証・変換

> **原則が B/C/D 層の都合で変えられることはない。**

---

## 3. Core Principles（普遍原則・最終形）

SCAI の価値中核を構成する原則群を、依存関係に基づき最適な順序に整理する。

### **3.1 Single Source of Truth（唯一の真実の源｜最上位原則）**

構造的な単一の“正”に基づき、分散する矛盾を許容しない。

### **3.2 Structured Representation（構造優越）**

意味は構造により決まり、文章は補助である。

### **3.3 Separation of Concerns（責務分離）**

層・役割・文書の混濁を防ぎ、構造の安定性を確保する。

### **3.4 Consistency（一貫性）**

命名・番号体系・粒度・構造は分野を跨いでも揺れない。

### **3.5 Minimalism（最小化）**

過剰な要素を排除し、必要十分な構造だけを維持する。

### **3.6 Interpretability（AI/Human Interpretability）**

AI が誤読しない構造と、人間に理解可能な文脈を両立させる。

### **3.7 Transparency（Structural Transparency）**

意図・関係・構造を隠さず、読み手とAIの双方にとって明確にする。

### **3.8 Traceability（追跡可能性）**

起源・根拠・参照関係が番号体系と構造によって辿れる。

### **3.9 Composability（合成可能性）**

独立した構造・手法が組み合わせ可能で、依存関係が単純であること。

### **3.10 Technology-Agnostic（技術非依存）**

形式やツールに依存せず、普遍的な抽象構造として成り立つ。

### **3.11 Lifecycle Discipline（ライフサイクル規律）**

生成・修正・廃止の状態遷移が秩序を持つこと。

### **3.12 Automation First（自動化優先）**

生成・検証・変換の自動化を前提として成果物を設計する。

---

## 4. 原則間の関係性（Principle Relations）

* **Single Source of Truth** は最上位原則であり、他原則の基盤となる。
* **Structured Representation → Interpretability → Automation** は直線的な依存関係を持つ。
* **Separation of Concerns** は階層境界を守ることで **Consistency** を保証する。
* **Minimalism** はすべての原則に横断的に影響し、腐敗防止のコアとなる。

原則間は競合せず、全体として SCAI の価値体系を構成する。

---

## 5. 改訂ポリシー（Revision Policy）

* G0100 は **最も変更されてはならない文書**である。
* 新原則の追加は慎重に行う。
* 原則の削除・統合は極力避ける。
* G0200（抽象規範）や B/C層（分野・手法）が原則を“理由”に変更される場合でも、
  **G0100 自体は揺らがないことが前提**である。

# G0200 – Meta Framework Rules（SCAI フレームワーク｜正式呼称：スカイ）

> **一言でいうと（Ultra Short Summary）**
> G0200 は、SCAI の **原則（G0100）を B/C 層へ翻訳するための抽象構造規範** を定義する文書である。
> 文章ではなく **構造が意味を決める** という思想を実装し、AI と人間の双方が誤解なく扱える「構造的な背骨」を提供する。
> **A → B → C の一方向構造** を保証し、逆流（下位による上位改変）を防ぐ役割を担う。

> **SCAI 補足（A0200 における位置づけ）**
>
> SCAI（Structured Cooperative AI Framework／スカイ）は、人間とAIが対等に協働し、構造化された文書を共通の基盤として作業する体系である。A0200 はその中核として、SCAI の理念（G0000）と原則（G0100）を B層（分野構造）および C層（手法）へ橋渡しするための「抽象構造規範」を定義する。これにより、SCAI 全体の構造的一貫性が保証される。（抽象規範・A/B/C層接続の中核・精密化版）

## 1. 目的（Purpose）

G0200 は G0100 の普遍原則を、B層（分野フレームワーク）および C層（手法）へ橋渡しするための **抽象構造規範** を定義する文書である。
文書形式や技術的仕様に依存せず、SCAI 全体系が一貫した構造を保つための“背骨”として機能する。

## 2. 適用範囲（Scope）

G0200 は以下すべてに適用される：

* A → B → C の階層構造

* 構造化データ（YAML/JSON/DSL）および文書双方に対する構造規律
* AI による生成・解析・検証を前提とした成果物全般

> ※ 本書は「構造規範」を扱い、具体フォーマット（YAMLキー名など）は B/C 層に記述する。

## 3. Artifact 抽象モデル（Abstract Artifact Model）

#### 3.x 図示（Artifact モデルの小型図）

```
┌────────────── Metadata Layer ──────────────┐
│ identifier / version / status / relations     │
└──────────────────────────────────────────────┘
                 │（構造を決定する）
                 ▼
┌────────────── Structure Layer ─────────────┐
│ sectionId / ruleId / hierarchy / schema       │
└──────────────────────────────────────────────┘
                 │（文章は従属）
                 ▼
┌────────────── Content Layer ───────────────┐
│ 説明文 / 図 / 表（構造の補助）               │
└──────────────────────────────────────────────┘
```

### 3.x Artifact 具体例（Simple Example）

以下は、SCAI の Artifact モデルを最小構成で表現した例である。

```
identifier: G0201
version: 1.0.0
status: draft
relations:
  - ref: G0100
    type: derives

structure:
  - sectionId: 1
    title: Purpose
  - sectionId: 2
    title: Rules
      items:
        - ruleId: 2-1
          title: Structure-Deterministic Meaning
        - ruleId: 2-2
          title: No Ambiguity

content:
  Purpose:
    本文では、規範の目的を記述する（構造に従属）
  Rules:
    2-1: 意味は構造によって一意に決まることを記述する
    2-2: 暗黙的記述禁止について説明する
```

この例のポイント：

* **意味は structure 内の sectionId / ruleId により決まる**
* content は構造を補助するだけ
* relations により依存関係を明示
* 番号体系（identifier）が階層の意味を保証する

SCAI のすべての成果物は Artifact として以下の 3 層に構造化される。

### 3.1 Metadata Layer

* identifier（G番号 / P番号）
* version / status
* created / updated
* relations（参照・依存・満たす基準など）

### 3.2 Structure Layer

* 階層構造（sections / items / phases など）
* 固定的な ID 体系（sectionId / ruleId / phaseId）
* Schema と Documentation を明確に分離する（Structure-First）

### 3.3 Content Layer

* 説明文
* 表・図・解説
* 例示（Structure の補助）

> 意味は構造で決まり、文章は構造の補助として扱う。

## 4. 参照モデル（Reference Model）

### 4.x Cross-Layer 参照の具体例（Simple Reference Example）

以下は、A → B → C の方向で参照する例である。

```
# A層（原則）
G0100-3.2 Structured Representation
  → "意味は構造で決まる" を定義

# B層（分野構造）
G0200（YAML / Spec Framework）
  - この分野では、構造を YAML Schema で表現する
  - G0100-3.2 を根拠にしつつ、分野固有の規範として明文化

# C層（手法）
G0203 InstructionPatterns
  - YAML 構造を前提としたプロンプトパターン
  - G0200 の規範（構造優先）を反映
  - G0100 への直接参照は禁止（逆流防止）
```

ポイント：

* **A → B → C の流れで参照が落とし込まれる**
* C は必ず B を介して A を間接参照する
* A への直接参照（C → A）は禁止、必要なら B 層が吸収する

階層の独立性を保ち、逆流（下位→上位の汚染）を防ぐため、参照構造を厳密に定義する。

### 4.1 Logical Reference（論理参照）

* identifier（Gxxxx / Pxxxx）による一意参照
* A → B、B → C の順方向のみ許可

### 4.2 Structural Reference（内部構造参照）

* sectionId / itemId による階層内参照
* 構造位置が変わっても意味が変わらない設計（Structure-Deterministic Meaning）を必須とする

### 4.3 Cross-Layer Reference（層間参照）

* **A → B → C** の方向のみ許可
* **C → A** の直接参照は禁止
  → 必要に応じて G0200 が抽象化して吸収する

## 6. AI 可読性要件（AI Readability Requirements・強化版）

AI による自動処理を前提とし、以下の要件を満たす構造のみを SCAI として認める。

* 暗黙の前提の禁止（すべて明示）

* A/B/C の役割が完全分離されていること
* 記述の副作用を持たない（上位層の意味を変えない）
* Schema と Documentation の混濁禁止

* 手法の都合で理念を変えることは禁止
* 必要な場合は G0200（Meta）が吸収し抽象化する

# G0300 – Framework Overview（SCAI フレームワーク｜正式呼称：スカイ）

> **SCAI 追加説明（Overview 拡張）**
>
> SCAI（Structured Cooperative AI Framework／スカイ）は、人間とAIが対等に協働し、構造化された文書を共通の基盤として扱うための総合フレームワークである。G0300（Overview）は、SCAI 全体を俯瞰するための“地図”として機能し、理念（G0000）・原則（G0100）・構造規範（G0200）・体系目録（G0400）を横断的に理解するための位置づけを提供する。
>
> SCAI における A/B/C/D の4層構造は、単なる文書分類ではなく、人間とAIが誤解なく協働するための構造的役割分担である。A層は共通の思想と原則を定め、B層は分野単位の構造ルールを定義し、C層は具体的な手法を提供し、D層はプロジェクト適用を担う。この“上位→下位への一方向構造”こそが、SCAI の一貫性と可読性の核心である。

> **SCAI（Structured Cooperative AI Framework）とは？**
>
> SCAI（スカイ）は、人間とAIが上下関係なく対等に協働し、構造化された文書と共通基盤を通じて作業を進めるための体系である。A層はその理念・原則・構造規範を定義し、全体の背骨となる。（全体構造の地図・簡素化版）

## 1. 目的（Purpose）

G0300 は SCAI の **全体像を俯瞰するための地図** である。
詳細な規範（G0200）や具体的な体系（G0400）とは異なり、
**“構造をどう理解すればよいか” を最短距離で示す** ことを目的とする。

---

## 2. Framework の4層構造（A/B/C/D）

SCAI は以下の 4 つの層によって構成される。

### 2.1 A層（理念・原則・抽象規範）

* Foundation（G0000）
* Core Principles（G0100）
* Meta Rules（G0200）
* Overview（本書）
* Framework Tree（G0400）

**役割：** WHY（存在理由）・WHAT（原則）・HOW（抽象規範）を定義する最上位層。

### 2.2 B層（分野フレームワーク：Gxx00）

* 分野ID（01〜99）で管理される中間フレームワーク層
* 分野横断の一貫性と役割の切り分けを担う

例：01 Document / 02 YAML / 03 SCD / 04 Coding …

### 2.3 C層（手法・テンプレート：Gxx01〜99）

* B層に属する分野ごとの具体的な手法群
* **Gxx00 → Gxx01〜99** の構造で分野と一貫して紐づく

### 2.4 D層（プロジェクト：Pxxxx）

* 標準（G系）とは独立したプロジェクト成果物領域

## 5. A→B→C→D の基本構造（最重要図）

SCAI を理解する最短経路は以下の一本の流れである。

```
A（理念・原則）
   ↓ 翻訳
B（分野構造）
   ↓ 具現化
C（手法）
   ↓ 適用
D（プロジェクト）
```

この順方向のみを許可し、逆流（C→A）や混濁を防ぐことで、 体系全体の一貫性と可読性を保証する。
