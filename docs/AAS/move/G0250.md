## 1. Purpose（目的）

本書は、SCAI のすべての成果物が **一貫した最小構造で記述されるための共通レイヤ** を定義する。

本書は B層の詳細規則より上位に位置し、SCAI の思想（G0100）・永続原則（G0200）・構造規範（G0300）の要求を、文書形式の要件として具現化する役割をもつ。

本書は **Minimal Structure（最小構造）** のみを扱い、詳細仕様は B層へ委譲する。

---

## 2. Scope（適用範囲）

本書は以下すべてに適用される：

* A〜D層の SCAI 文書
* すべてのカテゴリ（OVR/REQ/ARC/TST/OPS/SECなど）
* Markdown / YAML / JSON / TXT を含むすべての形式
* AI 生成物・人間の記述物の双方

---

## 3. Core Rules（最小文書構造規範）

### 3.1 Front Matter（必須）

すべての文書は CreativeWork 形式の FM を必須とする。

必須キー：

```
schema: https://schema.org/CreativeWork
type: CreativeWork
identifier: "Gxxxx" or "Pxxxx"
name: "文書名（日本語）"
version: "1.0.0"
inLanguage: "ja"
datePublished: "YYYY-MM-DD"
description: "文書概要"
```

### 3.2 Table of Contents（目次）

FM の直後に配置する。章番号ベースで自動生成を前提とする。

### 3.3 Document Title（文書タイトル）

H1（#）で記述し、番号やカテゴリは含めない。

### 3.4 Section Structure（章構造）

```
# 文書タイトル
## 1. 第一章
### 1.1 第二階層
```

H1 → タイトル、H2 → 第一章、H3 は標準最大階層とし、H4 以降の使用は原則として推奨しない（詳細規則は B層に委譲する）。

### 3.5 Code Blocks（コードブロック）

AI可読性のため、コードブロックは以下を必須とする：

* 三連バッククォート（`\````）を使用する
* **言語名を必ず指定する（例：```yaml）**
* 言語名は GitHub Flavored Markdown (GFM) の標準名称に従う

---

### 3.6 Links and Anchors Links and Anchors

```
[詳細は 2.3](#2-3)
```

アンカーは自動生成を前提とし、手動変更禁止。

### 3.7 Encoding / Character Set

* UTF-8（BOMなし）
* LF（Unix）
* ASCII以外の記号は最小限

### 3.8 File Naming（最小規範）

ASCIIの安全文字のみを使用。拡張子は `.md`。
詳細命名規則は B層に委譲。

---

## 3.9 Markdown Specification（Markdown仕様）

本フレームワークは CommonMark および GitHub Flavored Markdown (GFM) を前提とする。A層として以下を定義する：

**MUST（必須）**

* GFM準拠で記述する
* 独自拡張 Markdown を使用しない（Pandoc, Extra, Obsidian, Notion など）
* HTMLタグを使用しない（<div>, <span>, <br> 等）

**MUST（必須）**

* 箇条書き記号は `-` を用いる
* 構文は GFM 標準の最小範囲に留める

詳細仕様は B層で取り扱う。

---

## 3.10 Prohibitions（禁止事項）

A層として以下の書式は禁止する：

* **H4 以降の見出し階層**
* **HTML タグの混在**
* **GFM 非準拠の Markdown 構文**
* **コードブロックの言語指定なし表記**

---

## 3.11 Strict Structural Rules（厳格構造規範）

A層に属する文書の構造安定性を高めるため、以下を適用する：

**MUST（必須）**

* 見出しは H1 → H2 → H3 のみを使用（H3 を最大階層とする）
* コードブロックは ``` + 言語名を必須とし、閉じ忘れを禁止する

**SHOULD（推奨）**

* **見出し（H1/H2/H3）の前後には必ず 1 行の空行を置く**
* **箇条書きは `-` を統一使用し、必ず従うこと（ネストは2段階まで）**
* テキスト中の Markdown 構文は GFM 標準に準拠する

---

## 3.10 Strict Structural Rules（書式厳密化ルール）

A層に属する文書の構造安定性を高めるため、以下の厳密ルールを適用する：

* **H4 以降の見出しは使用禁止とする（H3 を最大階層とする）**
* **HTML タグ（<div>, <span>, <br> など）の使用を禁止する**
* **見出し（H1/H2/H3）の前後には 1 行の空行を置くことを推奨する**
* **コードブロックは ``` + 言語名を必須とし、閉じ忘れを禁止する**
* **箇条書きは `-` で統一する（ネストは2段階までを推奨）**
* **テキスト中の Markdown 構文は GFM 標準以外を使用しない**

---

本フレームワークは、Markdown 記法として **CommonMark および GitHub Flavored Markdown (GFM)** を前提とする。

* 独自拡張 Markdown（Pandoc, Extra, Obsidian, Notion など）は使用しない
* GFM に準拠することで構造の揺らぎを避ける
* 本書では詳細構文を規定せず、最小限の使用基準のみを定義する（詳細は B層に委譲）

---

## 4. Non-goals（対象外）

本書に含まれない事項：

* 文書カテゴリ詳細（OVR/REQ/ARC/TST 等）
* Markdown の細則（セル改行など）
* Mermaid/PlantUML の仕様
* YAML/SCD/OPS の個別ルール
* 編集・レビュー手順
* Multi-Volume 規則

## 6. Revision Policy（改訂ポリシー）

* Minimal Structure の原則を損なわない範囲で改訂する。
* 詳細規則は B層へ委譲することで A層の肥大化を防ぐ。
* Artifactモデル（G0300）との整合性を維持する。
* 構造拡張が必要な場合は G0400（番号規範）と協調して行う。
