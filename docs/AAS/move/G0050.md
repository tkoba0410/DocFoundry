# G0050 – Numbering Policy（SCAI 番号体系ポリシー｜正式呼称：スカイ）

## 1. 目的（Purpose）
本書 G0050 は、SCAI（Structured Cooperative AI Framework／スカイ）における**番号体系の公式ルール**を定義する文書である。番号体系は単なる識別子ではなく、SCAI 全体の構造的一貫性・参照可能性・意味の安定性を担保する「構造そのもの」である。

番号は **層・責務・分野・手法の役割を表す構造的要素**として扱う。

---

## 2. 基本原則（Core Principles of Numbering）
番号体系は以下の原則に従う：

### **2.1 Structure-Deterministic Meaning（意味は番号構造で決まる）**
番号の位置（層・上2桁・下2桁）が持つ意味は固定であり、文章によって変更されてはならない。

### **2.2 一方向構造（A → B → C → D）**
番号体系も層構造に従い、上位層が下位層を参照し、逆方向を禁止する。

### **2.3 粒度の不変性（Granularity Consistency）**
分野 ID（01〜99）や手法 ID（01〜99）は固定粒度を持ち、分野間で揺らがない。

### **2.4 固定的な責務（Responsibility Anchoring）**
番号は成果物の責務を表す。番号が変われば責務も変わる。

### **2.5 冗長性排除（Minimality）**
必要以上に番号体系を複雑化させない。記述揺れ・重複を発生させない。

---

## 3. 全体構造（Global Structure of Numbering）
SCAI の番号体系は **G（標準）／P（プロジェクト）** を軸とし、層・分野・手法を以下のように表現する。

### **3.1 A層（G0000〜G0099）**
- 目的：思想・原則・抽象規範
- 上2桁：00
- 下2桁：00〜99（文書区分）
- 例：
  - G0000 Foundation
  - G0100 Core Principles
  - G0200 Meta Rules
  - G0300 Overview
  - G0400 Tree
  - G0050 NumberingPolicy（本書）

### **3.2 B層（Gxx00）**
- 目的：分野フレームワーク
- 上2桁：分野 ID（01〜99）
- 下2桁：常に 00（分野を表す）
- 例：G0300（SCD 分野）

### **3.3 C層（Gxx01〜Gxx99）**
- 目的：分野固有手法
- 上2桁：分野 ID（B層と一致）
- 下2桁：手法 ID（01〜99）
- 例：G0304（SCD 分野の手法 04）

### **3.4 D層（Pxxxx）**
- 目的：プロジェクト領域
- 0000〜9999 を自由に使用可能（標準とは混在しない）
- 例：P0101（プロジェクト固有手法 01-01）

---

## 4. 番号の意味（Meaning of Number Components）
番号は以下の意味構造を持つ：

```
G 03 04
│ │  └── 手法 ID（C層のみ）
│ └──── 分野 ID（01〜99）
└────── 標準層（G = 標準 / P = プロジェクト）
```

**番号を見るだけで、成果物の責務・位置づけ・階層が理解できることが必須条件。**

---

## 5. 禁止事項（Prohibited Patterns）
番号体系の一貫性を損なう以下の行為は禁止する：

- B層（Gxx00）を手法に使う（誤用）
- C層（Gxx01〜99）が A層（G00xx）を直接参照する
- D層（Pxxxx）が G番号の意味を上書きする
- 分野 ID を途中で変更する（意味を破壊）
- 既存番号の勝手な再利用

---

## 6. 変更ポリシー（Change Policy）
番号体系の変更は原則として次を満たす必要がある：

- **後方互換性の維持**（既存番号を変更しない）
- **上位層の変更を下位層に伝播しない**（逆流禁止）
- **分野 ID（01〜99）の追加は自由だが削除は慎重に行う**
- **手法 ID（01〜99）は固定の粒度を維持する**
- A層の番号は特に変更を避ける（SCAI の基盤）

---

## 8. 具体例（Practical Examples）

### **8.1 A→B→C の番号の流れ（例）**
```
G0000  Foundation（思想）
G0100  Core Principles（原則）
G0200  Meta Framework Rules（抽象規範）

↓ A層の思想・原則を翻訳

G0300  SCD Framework（分野 03 のフレームワーク）

↓ 分野構造を手法へ具体化

G0304  SCD-ConformancePhase（手法 04）
```
**ポイント：**
- 分野ID 03 が A→B→C で一貫して維持される。
- 手法番号 04 は C層の粒度を示す。
- A層 → B層 → C層 の一方向構造。

---

### **8.2 G 番号の読み方例**
```
G0702
││└─ 02 = テスト分野（07）の手法 02
│└── 07 = 分野 ID（Testing）
└──── G = 標準（SCAI 標準層）
```
**意味：**「テスト分野（07）の手法 02」

---

### **8.3 禁止例（アンチパターン）**
```
❌ C層（G0702）が A層（G0100）を直接参照する
❌ 分野IDを途中で変更して G0300 → G0800 にする
❌ B層（G0300）に手法（内容）を書き込む
❌ P番号（P1234）で標準ルールを定義し始める
```
**理由：**
- 逆流（C→A）は構造の破壊
- 分野IDを変えると参照の意味が壊れる
- B層は構造のみ、手法はC層に限定
- D層（Pxxxx）は標準（G系）と混在不可

---

## 9. 補足図（Reference Flow Diagram）
```

          │  一方向
          ▼

          │  一貫性保持

```
**C→A や D→B の逆流は禁止。**

## 10. 追加規範（Advanced Numbering Rules）

### **10.1 予約領域（Reserved Ranges）**
SCAI では将来の拡張と衝突回避のため、以下の番号帯を予約する：
```
G0001〜G0009   A層の将来利用枠
G0090〜G0099   A層の補助文書
Gxx90〜Gxx99   C層の拡張枠（拡張手法）
P9000〜P9999   プロジェクトの拡張枠
```
**目的：** 体系が成長した際にも構造断絶が発生しないようにする。

---

### **10.2 番号衝突（Collision）の扱い**
番号衝突が発生した場合の公式処理手順：
```
1. 衝突している番号の責務を確認する
2. 原則として既存番号を優先し、後発番号を再割当てする
3. B層の再割当ては原則禁止（分野の同一性が崩壊するため）
4. C層手法番号（01〜99）は再割当て可能だが、履歴に明示する
5. D層（Pxxxx）は自由領域のため衝突時は付番し直す
```
**重要：** 番号の再利用は禁止。廃止番号は「Retired」として扱う。

---

### **10.3 番号移行（Migration Policy）**
過去の番号体系から SCAI 体系への移行は以下に従う：
```
- 意味の同一性が保たれる場合のみ移行可能
- 番号変更は成果物の責務変更とみなす
- 旧番号は廃止ではなく "deprecated" として追跡可能にする
- 大規模移行は G0051（MigrationRecord）に記録する
```

---

### **10.4 番号のエイリアス禁止（Alias Prohibition）**
複数の番号を同一の成果物に割り当てること（Alias）は**全面禁止**。
```
理由：
- Structure-Deterministic Meaning が崩れる
- 追跡可能性の破壊
- 参照整合性の低下
```

例：
```
❌ G0304 と G0307 を "同じ手法" として扱う
❌ G0100 の別名として G0199 を使う
```

---

### **10.5 バージョン管理との関係（Numbering vs. Versioning）**
番号は構造を表し、バージョンは履歴を表す。
```
番号：成果物の「責務・階層・分野」を表す（不変）
バージョン：成果物の「内容の変化」を表す（可変）
```
**番号を変える＝別の成果物になる。**

## 8. まとめ（Summary）
G0050 は SCAI の番号体系を統一的に扱うための中核文書であり、A/B/C/D の構造的役割を守るためのルールセットである。番号体系は意味そのものであり、構造的秩序と AI/Human 可読性の双方にとって必須の基盤である。
