# G0200 – Meta Framework Rules（SCAI フレームワーク｜正式呼称：スカイ）

> **一言でいうと（Ultra Short Summary）**
> G0200 は、SCAI の **原則（G0100）を B/C 層へ翻訳するための抽象構造規範** を定義する文書である。
> 文章ではなく **構造が意味を決める** という思想を実装し、AI と人間の双方が誤解なく扱える「構造的な背骨」を提供する。
> **A → B → C の一方向構造** を保証し、逆流（下位による上位改変）を防ぐ役割を担う。

> **SCAI 補足（A0200 における位置づけ）**
>
> SCAI（Structured Cooperative AI Framework／スカイ）は、人間とAIが対等に協働し、構造化された文書を共通の基盤として作業する体系である。A0200 はその中核として、SCAI の理念（G0000）と原則（G0100）を B層（分野構造）および C層（手法）へ橋渡しするための「抽象構造規範」を定義する。これにより、SCAI 全体の構造的一貫性が保証される。（抽象規範・A/B/C層接続の中核・精密化版）

## 1. 目的（Purpose）

G0200 は G0100 の普遍原則を、B層（分野フレームワーク）および C層（手法）へ橋渡しするための **抽象構造規範** を定義する文書である。
文書形式や技術的仕様に依存せず、SCAI 全体系が一貫した構造を保つための“背骨”として機能する。

---

## 2. 適用範囲（Scope）

G0200 は以下すべてに適用される：

* A → B → C の階層構造
* すべての Artifact（文書・Spec・Checklist・SCD・Instruction・コード規範など）
* 構造化データ（YAML/JSON/DSL）および文書双方に対する構造規律
* AI による生成・解析・検証を前提とした成果物全般

> ※ 本書は「構造規範」を扱い、具体フォーマット（YAMLキー名など）は B/C 層に記述する。

---

## 3. Artifact 抽象モデル（Abstract Artifact Model）

#### 3.x 図示（Artifact モデルの小型図）

```
┌────────────── Metadata Layer ──────────────┐
│ identifier / version / status / relations     │
└──────────────────────────────────────────────┘
                 │（構造を決定する）
                 ▼
┌────────────── Structure Layer ─────────────┐
│ sectionId / ruleId / hierarchy / schema       │
└──────────────────────────────────────────────┘
                 │（文章は従属）
                 ▼
┌────────────── Content Layer ───────────────┐
│ 説明文 / 図 / 表（構造の補助）               │
└──────────────────────────────────────────────┘
```

### 3.x Artifact 具体例（Simple Example）

以下は、SCAI の Artifact モデルを最小構成で表現した例である。

```
identifier: G0201
version: 1.0.0
status: draft
relations:
  - ref: G0100
    type: derives

structure:
  - sectionId: 1
    title: Purpose
  - sectionId: 2
    title: Rules
      items:
        - ruleId: 2-1
          title: Structure-Deterministic Meaning
        - ruleId: 2-2
          title: No Ambiguity

content:
  Purpose:
    本文では、規範の目的を記述する（構造に従属）
  Rules:
    2-1: 意味は構造によって一意に決まることを記述する
    2-2: 暗黙的記述禁止について説明する
```

この例のポイント：

* **意味は structure 内の sectionId / ruleId により決まる**
* content は構造を補助するだけ
* relations により依存関係を明示
* 番号体系（identifier）が階層の意味を保証する

SCAI のすべての成果物は Artifact として以下の 3 層に構造化される。

### 3.1 Metadata Layer

* identifier（G番号 / P番号）
* version / status
* created / updated
* relations（参照・依存・満たす基準など）

### 3.2 Structure Layer

* 階層構造（sections / items / phases など）
* 固定的な ID 体系（sectionId / ruleId / phaseId）
* Schema と Documentation を明確に分離する（Structure-First）

### 3.3 Content Layer

* 説明文
* 表・図・解説
* 例示（Structure の補助）

> 意味は構造で決まり、文章は構造の補助として扱う。

## 4. 参照モデル（Reference Model）

### 4.x Cross-Layer 参照の具体例（Simple Reference Example）

以下は、A → B → C の方向で参照する例である。

```
# A層（原則）
G0100-3.2 Structured Representation
  → "意味は構造で決まる" を定義

# B層（分野構造）
G0200（YAML / Spec Framework）
  - この分野では、構造を YAML Schema で表現する
  - G0100-3.2 を根拠にしつつ、分野固有の規範として明文化

# C層（手法）
G0203 InstructionPatterns
  - YAML 構造を前提としたプロンプトパターン
  - G0200 の規範（構造優先）を反映
  - G0100 への直接参照は禁止（逆流防止）
```

ポイント：

* **A → B → C の流れで参照が落とし込まれる**
* C は必ず B を介して A を間接参照する
* A への直接参照（C → A）は禁止、必要なら B 層が吸収する

階層の独立性を保ち、逆流（下位→上位の汚染）を防ぐため、参照構造を厳密に定義する。

### 4.1 Logical Reference（論理参照）

* identifier（Gxxxx / Pxxxx）による一意参照
* A → B、B → C の順方向のみ許可

### 4.2 Structural Reference（内部構造参照）

* sectionId / itemId による階層内参照
* 構造位置が変わっても意味が変わらない設計（Structure-Deterministic Meaning）を必須とする

### 4.3 Cross-Layer Reference（層間参照）

* **A → B → C** の方向のみ許可
* **C → A** の直接参照は禁止
  → 必要に応じて G0200 が抽象化して吸収する

## 5. 番号体系との関係（Numbering System Integration）

G0200 は番号体系を「構造規律そのもの」として扱うが、**詳細仕様は G0400（Tree）および G0050（番号規則文書）に委譲する**。

### G0200 が保証すべき要点

* A層：G00xx は理念・原則・抽象規範のみ
* B層：Gxx00 は分野構造（ID＝分野そのもの）
* C層：Gxx01〜 は分野固有の手法（ID＝手法）
* D層：Pxxxx はプロジェクト独立領域

> 番号体系は構造そのものの一部であり、SCAI の参照一貫性を担保する。

## 6. AI 可読性要件（AI Readability Requirements・強化版）

AI による自動処理を前提とし、以下の要件を満たす構造のみを SCAI として認める。

* **Structure-Deterministic Meaning**（意味は構造で決まり文章依存しない）
* 情報粒度の一貫性（過不足の排除）
* 暗黙の前提の禁止（すべて明示）
* 番号体系による参照の明確化
* A/B/C の役割が完全分離されていること
* 記述の副作用を持たない（上位層の意味を変えない）
* Schema と Documentation の混濁禁止

---

## 7. 層間統合規範（Layer Integration Rules）

### A → B（理念を分野構造へ翻訳）

* G0100 の原則を分野固有の構造規範へ落とし込む
* 分野横断で一貫性を持つこと（Consistency）

### B → C（構造を具体手法へ具現化）

* Gxx00 → Gxx01〜99 の関係を厳密に保持
* 手法は構造規範の具体化として派生する

### C → A（逆流禁止）

* 手法の都合で理念を変えることは禁止
* 必要な場合は G0200（Meta）が吸収し抽象化する

---

## 8. 改訂ポリシー（Revision Policy）

* G0200 は SCAI の“構造の背骨”であり変更は最小限
* 技術変化による抽象規範の拡張は許容（ただし原則に従う）
* G0100 と矛盾する場合、G0200 が調整される側である
* 番号体系の詳細変更は本書では行わず、G0400 / G0050 に委譲する
