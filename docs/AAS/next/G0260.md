# G0260 Document Production Workflow（Draft v0.2.0）

本書は、DocFoundary Framework における **文書生成の原則・仕組み・手順** を統合した A 層文書である。文書の「構造」を規定する G0250 と、Framework 全体の理念を定める G0001 を受け、実際の文書生成・維持・検証プロセスを定義する。

文書生成は単なるテンプレート適用ではなく、**A 層仕様 → 機械用仕様 → AI 生成 → 検証 → 人間による内容調整** の循環をもつ反復過程であり、本書はその具体的な流れを体系化する。

## 1. Purpose（目的）
本書は、DocFoundary に属する成果物が **一貫性・再現性・構造安定性** をもって生成されるための文書生成ワークフローを定義する。AI の機能と人間の判断を最適に組み合わせることで、揺らぎのない文書体系を長期的に維持することを目的とする。

## 2. Scope（適用範囲）
本書は以下に適用される：

- DocFoundary Framework におけるすべてのカテゴリ（OVR / REQ / ARC / TST / OPS / SEC）
- A〜D 層に属するすべての文書
- AI 生成文書・人間作成文書の双方
- 機械可読仕様（B 層）の生成と運用

## 3. Workflow Overview（ワークフローの概要）
文書生成は以下のステップで構成される：

1. **A 層文書の確立**（G0001, G0250, G0260）
2. **A 層文書からの機械用仕様（B 層）生成**
3. **AI による文書ドラフト生成（C 層）**
4. **機械用チェックによる検証（Validation）**
5. **人間による内容調整（Interpretation）**
6. **文書の確定・運用層（D 層）への統合**

この循環は、文書体系全体が永続的に改善され続けるための基盤となる。

## 4. Single Source of Truth（唯一の真実）
文書体系は **A 層文書を唯一の真実（SSOT）** として構築される。A 層には：

- Vision / Philosophy（G0001）
- Minimal Structure（G0250）
- Document Production Workflow（本書）

が含まれ、これらの仕様が機械用仕様・内容仕様・運用仕様をすべて規定する。

## 5. Machine-Readable Specification（機械用仕様）
A 層文書から派生する機械用文書は以下を含む：

### 5.1 Instruction Specification（指示書）
AI が文書を生成する際に従うべき必須規範を明記する。文書スケルトン、禁止事項、要件を含む。

### 5.2 Validation Checklist（確認書）
生成された文書が仕様に適合しているかを検証するチェックリスト。AI による自動検証に使用される。

### 5.3 Detailed Specification（詳細仕様）
文書構造・形式規則を正規表現や YAML 形式で定義する半形式仕様。将来的な Linter の基盤となる。

これら 3 種が最小構成であり、必要に応じてテンプレート仕様や実装仕様が追加される。

## 6. Formalization Model（A→B→C の段階的形式化）
A 層には理念・意図・抽象規則が含まれるため揺らぎが存在する。これを段階的に形式化することで、機械が処理可能な文書体系へと変換する。

- **A 層：自然言語仕様（理念・抽象）**
- **B 層：半形式仕様（YAML / ルール群）**
- **C 層：形式仕様（正規表現・スキーマ・Lint 仕様）**

この段階的形式化により、A 層の揺らぎを損なうことなく、機械的整合性が担保される。

## 7. Document Generation Loop（文書生成ループ）
DocFoundary の文書作成は以下のループを持つ：

1. **A 層仕様の確立**
2. **B 層仕様の生成（指示書／検証書／詳細仕様）**
3. **AI によるドラフト生成**
4. **チェックリストによる検証**
5. **人間による内容調整**
6. **文書の確定・公開**

このループは文書の構造的健全性を保証し、AI 時代における文書生成の品質を最大化する。

## 8. Roles and Responsibilities（責務）
- **A 層編集者**：理念・構造・生成ルールの定義
- **AI モデル**：生成と検証の自動化
- **レビュー担当者**：意味・内容・妥当性の調整
- **運用担当者**：CI / Linter などの運用管理

## 9. Non-goals（対象外）
- 個別カテゴリ文書の内容規範（REQ, ARC など）
- ソフトウェア仕様や運用品質保証
- ツールチェーンの具体構成
- Linter 実装そのもの

## 10. Future Direction（未来方向性）
DocFoundary は、A 層文書を読んで **AI が B/C/D 層を自律生成する完全自動化** を最終目標とする。本書はその過渡期における最適な仕組みを示すものであり、将来の自律型文書体系への橋渡しとして機能する。
