# G0250 Minimal Document Structure v1.1.2（A層・最終版）

本書は、SCAI に属するすべての成果物が **一貫した最小構造（Minimal Structure）** を用いて記述されるための A 層文書である。A 層として必要な範囲に限定し、構造揺らぎ・書式揺らぎ・章番号揺らぎを完全に排除した最終版である。

---

## 1. Purpose（目的）

本書は A 層に属する文書が統一構造をもち、あらゆるカテゴリ（OVR / REQ / ARC / TST / OPS / SEC）において **揺らぎなく読み書き可能な形式基盤** を提供することを目的とする。

Minimal Structure（最小文書構造）のみを扱い、詳細規則やフォーマット仕様は B 層に委譲する。

---

## 2. Scope（適用範囲）

本書は以下に適用される：

* A〜D 層すべての文書
* すべてのカテゴリ（OVR / REQ / ARC / TST / OPS / SEC）
* Markdown / YAML / JSON / TXT など、すべての文書形式
* AI 生成文書・人間作成文書の双方

---

## 3. Minimal Structure Rules（最小構造規範）

### 3.1 Front Matter（必須）

文書は必ず CreativeWork 形式の Front Matter（FM）を最上部に持つ。必須キーは以下の通り：

```yaml
schema: "https://schema.org/CreativeWork"
type: CreativeWork
identifier: "Gxxxx" または "Pxxxx"
name: "文書名（日本語）"
version: "1.0.0"
inLanguage: "ja"
datePublished: "YYYY-MM-DD"
description: "文書概要"
```

FM の位置は揺らぎを避けるため、**文書最上部に固定**される。

### 3.2 Table of Contents（目次）

FM（Front Matter）の直後に **必ず** Table of Contents（TOC）を配置する。  
TOC は H2/H3 の章構造に基づき自動生成されるものとし、  
TOC を省略することはできない。

### 3.3 Document Title（文書タイトル）

文書タイトルは **H1（#）を用いて 1 回のみ** 記述する。識別子、カテゴリ、番号を含めない。FM と TOC の次に配置する。

### 3.4 Heading Rules（見出し規則）

見出し階層は以下に固定される：

* **H1**：文書タイトル（1 回のみ）
* **H2**：第一章
* **H3**：第二階層（最大階層）
* **H4 以降は禁止**

見出し前後には 1 行の空行を置く（SHOULD）。

### 3.5 Markdown Rules（Markdown 規範）

本フレームワークは **CommonMark / GitHub Flavored Markdown（GFM）** を基準とする。

**MUST**

* GFM 標準に準拠する
* HTML タグ（div, span, br など）を使用しない
* 箇条書きは `-` に統一する
* コードブロックは「``` + 言語名」を必須とする
* Pandoc / Obsidian 等の独自拡張 Markdown を使用しない
* Front Matter 内の値に Markdown リンク表記（`[text](url)`）を使用しない
* 水平線（区切り線）は `---` のみ使用し、`***` や `___`、長い罫線（`------` など）は使用しない

**SHOULD**

* 箇条書きのネストは 2 階層まで
* 記号類は ASCII を原則とし、特殊記号は最小限にする

### 3.6 Code Block Rules（コードブロック規範）

AI 可読性と構造安定性のため、以下を厳守する：

* 三連バッククォートのコードブロックのみを使用
* 言語名は GFM の標準名（yaml / json / markdown / csharp など）
* 閉じ忘れは禁止

### 3.7 File Naming and Encoding（命名と文字コード）

* 文字コード：UTF-8（BOM なし）
* 改行コード：LF（Unix）
* ファイル名は ASCII の安全文字のみ
* 拡張子は `.md`
* 詳細命名規則は B 層に委譲

### 3.8 Prohibitions（禁止事項）

A 層として以下を禁止する：

* H4 以降の見出し
* HTML タグ埋め込み（div, span, br 等）
* GFM 非準拠の Markdown 構文
* 言語名なしコードブロック
* GFM 標準外の水平線（長い罫線等）は禁止する

### 3.9 Strict Formatting Rules（書式厳密化ルール）

Minimal Structure の統一性を保証するため、以下を適用する：

**MUST**

* 見出しは H1 → H2 → H3 のみ
* コードブロックは必ず「``` + 言語名」を指定

**SHOULD**

* 見出し前後に 1 行の空行
* 箇条書きは `-` に統一し、ネストは 2 段階まで
* テキスト中の Markdown 構文は GFM の最小範囲内に留める

---

## 4. Non-goals（対象外）

A 層の範囲外であるため、本書は次を扱わない：

* 文書カテゴリ（OVR / REQ / ARC / TST 等）の内容仕様
* Markdown の詳細仕様（表組み・折返し・インデントなど）
* Mermaid / PlantUML 等の図表仕様
* YAML / SCD / OPS の個別形式仕様
* 編集・レビュー手順、運用ワークフロー

---

## 5. Relationship with Other A-layer Documents

* **G0100 Foundation**：思想レイヤの形式基盤
* **G0200 Core Principles**：Minimality / Interpretability の具体化
* **G0300 Meta Rules**：Artifact モデルの構造運用を補強
* **G0400 Numbering Policy**：識別子・ファイル名規範と連携
* **G0500 Overview**：全体構造の上位概念として本書を使用
* **G0600 Framework Tree**：体系化の基礎として本書を前提とする

---

## 6. Revision Policy（改訂ポリシー）

* Minimal Structure の原則を損なわない範囲で改訂する
* 詳細仕様は B 層へ委譲し、A 層の肥大化を防ぐ
* Artifact モデル（G0300）との整合を維持する
* 構造拡張が必要な場合は G0400（番号規範）と協調して実施する
